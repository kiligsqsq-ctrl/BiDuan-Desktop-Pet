# 《彼端》落地版产品计划

## 1. 产品定位

彼端是一款面向异地情侣的 PC 桌面陪伴软件。它不是普通宠物，也不是聊天工具替代品，而是把“对方正在陪着我”的感觉放在桌面上：一个会动、会回应、能显示情侣状态的小小陪伴入口。

第一版目标不是一次做完商业计划书里的 50+ 功能，而是先做一个能被真实情侣试用的 MVP，验证三件事：

- 用户愿不愿意让它长期停留在桌面。
- 情侣状态、轻互动、留言是否能带来温暖感。
- 本地数据和文件同步能否支撑早期体验验证。

## 2. 目标用户

- 18-35 岁异地情侣。
- 日常高频使用电脑的学生、自由职业者、办公室人群。
- 需要低打扰陪伴，不想一直打开聊天软件，但希望知道对方状态的人。

## 3. 第一版 MVP 范围

第一版只做 PC 本地应用，优先 Windows。核心原则是“可运行、可试用、可反馈”。

### 必做功能

- 桌面宠物：透明背景、置顶、拖动、GIF 动画、右键菜单。
- 动作系统：提供 11 类状态、61 个状态动作和 1 个拖拽动作。
- 动作联动：桌宠播放用户选定来源的状态，同类动作支持四档定时轮换。
- 情侣状态：本机只能设置“我的状态”，TA 的状态由对方设备同步，不能代替对方选择。
- 可滚动主菜单：窗口内容超出可视区域时支持滚轮和右侧纵向滚动条。
- 轻互动：轻戳、抱抱、喂糖、休息等温柔反馈。
- 情绪照顾值：心情、能量、想念三个指标，本地自动变化。
- 情侣纪念日：在一起天数、下一次纪念日倒计时。
- 留言信箱：本地保存给对方的话。
- 自动同步：双方选择同一个云盘共享文件夹后，自动交换状态、留言和互动。
- 文件同步：保留导出/导入同步文件作为备用方式。
- 系统托盘：支持隐藏/显示桌宠、快速状态、开机启动和安全退出。
- Windows 安装包：提供应用图标、桌面快捷方式、开始菜单和卸载入口。
- 本地持久化：设置和数据保存到电脑。

### 暂缓功能

- AI 照片转 Q 版形象。
- Spine 动画资产和复杂骨骼动画。
- 用户自制的完整动作包编辑器。
- 3D 情侣小屋。
- 多人小游戏。
- 商城、会员、支付。
- 端到端加密聊天。
- 移动端 App。

这些功能价值很高，但需要美术、后端、账号体系和较长测试周期，不适合作为第一版起步。

## 4. 第一版用户流程

1. 用户打开桌宠，桌面出现一个可拖动的小角色。
2. 用户双击桌宠进入控制台，填写自己和对方昵称、纪念日。
3. 用户设置自己的当前状态；对方状态只能由对方设备同步过来。
4. 想对方时点击“轻轻碰你”或写一条留言。
5. 双方选择同一个云盘共享文件夹完成自动同步，也可以手动导出同步文件。
6. 对方数据到达后，用户可选择让桌宠显示自己或对方的状态。

## 5. 技术方案

### 当前 MVP

- 客户端：Python + Tkinter。
- 数据存储：本地 JSON。
- 同步方式：云盘共享目录自动交换 JSON，手动导出/导入作为备用。
- 动画方式：Pillow 解码 GIF 帧，Tkinter Canvas 定时刷新。
- Windows 集成：Pystray 系统托盘、注册表开机启动、PyInstaller 和 Inno Setup。

选择这个方案的原因是开发和运行成本低，不依赖复杂环境，适合先把产品感觉做出来。

### 下一版联网架构

- 桌面客户端：Electron + React + TypeScript。
- 实时通信：WebSocket。
- 后端：Node.js 或 Go。
- 数据库：PostgreSQL + Redis。
- 同步模型：情侣绑定码、双人房间、状态广播、离线消息。
- 安全：HTTPS/WSS、密码哈希、敏感数据加密存储。

## 6. 版本路线

### 0.1 本地原型

- 完成桌面宠物、状态、互动、留言、本地保存、文件同步。
- 目标：找到 5-10 对情侣试用，观察是否愿意打开超过 3 天。

### 0.3 可安装 MVP（已完成）

- 增加应用品牌图标、系统托盘、开机启动和中文安装程序。
- 增加共享文件夹自动同步、系统通知和互动同步。
- 目标：交付给首批真实情侣直接安装试用。

### 0.4 动画动作 MVP（已完成）

- 接入 11 类状态 GIF 和 61 个动作变体。
- 增加开机招呼、状态联动、同类轮换和拖拽专用动画。
- 目标：验证“角色动作表达对方状态”是否提升桌面陪伴感。

### 0.4.1 动画体验修订（已完成）

- 去除透明窗口造成的粉紫色人物描边。
- 桌宠改为表现 TA 的同步状态，移除本机修改 TA 状态的入口。
- 增加 10 秒、30 秒、60 秒、5 分钟四档动作轮换和页面滚动条。

### 0.4.2 状态来源选择（已完成）

- 在“动作”页选择桌面角色显示自己的状态或 TA 的同步状态。
- 状态来源是本机偏好，两个人可以分别选择，不会互相覆盖。

### 0.5 账号与云端同步

- 增加账号、情侣绑定码、云端状态同步。
- 增加自动更新、崩溃日志和隐私设置。
- 目标：100 对情侣内测，次日留存超过 40%。

### 0.6 个性化

- 增加宠物皮肤、表情、动作包。
- 增加更细的状态和提醒。
- 目标：验证用户是否愿意自定义形象。

### 0.7 情侣空间

- 增加照片墙、纪念日时间线、共同愿望清单。
- 目标：让产品从“玩具”变成“共同空间”。

### 1.0 商业化版本

- 会员、装扮商店、跨平台客户端、隐私和安全完善。
- 目标：形成可持续收费模式。

## 7. 商业模式建议

第一阶段不要急着收费，优先打磨留存。商业化可以分三层：

- 免费：基础桌宠、基础状态、基础留言。
- 会员：多设备同步、高级动作、纪念日主题、私密空间。
- 商店：皮肤、动作包、家具、节日限定主题。

不建议第一版上广告。异地情侣陪伴产品需要信任感，广告会削弱亲密氛围。

## 8. 风险和应对

- 功能太大：先做桌宠陪伴闭环，砍掉高成本功能。
- 同步体验弱：第一版用文件同步验证需求，第二版再做服务器。
- 美术成本高：当前先使用统一 GIF 动作包，后续再接入动作包制作工具和 Spine。
- 隐私担忧：不读取聊天记录，不上传敏感文件，后续提供加密。
- 留存不足：重点观察用户是否愿意长期挂在桌面，而不是只看下载量。

## 9. 当前交付标准

本阶段完成后，应当具备：

- 一个能通过中文安装向导安装和卸载的 Windows 桌宠应用。
- 一个带软件图标、系统托盘和开机启动选项的常驻程序。
- 一套能随 11 类状态切换、随机轮换并响应拖拽的桌宠动画。
- 一条可供两台电脑实际试用的自动同步路径。
- 一份清晰的产品计划。
- 一个可以继续扩展到联网版的代码结构。
- 一个小白也能理解的运行说明。
