# 彼端桌宠产品路线图

本文描述 0.4.2 之后的建议更新方向。路线图用于排序和拆分工作，不代表发布日期承诺；每个阶段都应在真实情侣试用反馈后再决定是否进入下一阶段。

## 产品原则

1. **陪伴优先**：新功能必须增强“对方在身边”的感觉，而不是堆成另一个聊天软件。
2. **低打扰**：状态、互动和提醒应简短、可控、可关闭。
3. **隐私默认安全**：只收集完成功能所需的数据，明确本地与云端边界。
4. **先验证再扩张**：先完成双人闭环，再做商城、3D、小屋和跨平台。
5. **升级不丢数据**：后续版本必须兼容现有昵称、状态、留言和纪念日。

## P0：近期完善当前 MVP

目标是让 5-10 对情侣能够连续试用一周，并获得可靠反馈。

- 新手引导：首次启动分步完成昵称、纪念日、状态来源和同步设置。
- 同步可视化：明确显示“已连接”“等待云盘”“最近同步”“同步失败”。
- 数据备份：一键导出和恢复完整本地数据。
- 动作包校验：检测缺失、损坏、尺寸异常和帧率异常的 GIF。
- 体验设置：气泡开关、通知开关、桌宠大小、静音时段。
- 稳定性：启动失败日志、异常恢复、低内存模式和长时间运行测试。
- 安装体验：代码签名、版本升级覆盖安装和卸载选项说明。

完成标准：连续运行 24 小时无明显内存增长；同步失败能被用户理解和恢复；升级安装不丢数据。

## 0.5：账号、情侣绑定与云同步

目标是替换共享文件夹方案，让异地双方无需配置第三方云盘即可连接。

### 用户功能

- 邮箱或手机号登录，也可以评估微信登录。
- 一次性情侣邀请码和绑定确认。
- 当前绑定关系、设备列表、解绑和换绑保护。
- 状态实时同步、轻互动实时送达、离线消息补发。
- 在线状态和最后同步时间，但不做精确位置或隐性监控。
- 本地数据迁移到云端，并允许继续导出个人数据。

### 技术基础

- HTTPS/WSS API、WebSocket 实时通道和离线队列。
- PostgreSQL 保存账号和情侣空间数据，Redis 保存短期连接状态。
- 密码哈希、访问令牌轮换、频率限制和审计日志。
- 明确的隐私政策、账号删除和数据删除流程。
- 自动更新、崩溃日志和基础运行监控。

完成标准：两台不在同一网络的电脑可通过绑定码连接；断网重连后状态和留言不丢失；用户可以解绑并删除账号数据。

## 0.6：个性化与动作包

目标是让角色更像“两个人共同选择的陪伴形象”。

- 上传一整套自定义 GIF 动作包，而不只是单张静态图片。
- 动作映射编辑器：为工作、吃饭、睡觉等状态指定多个 GIF。
- 动作预览、排序、启用/停用和随机权重。
- 桌宠缩放、左右朝向、气泡样式和节日主题。
- 官方基础角色与情侣成对角色。
- AI 照片转 Q 版形象的可行性验证，必须包含肖像隐私和生成授权说明。

完成标准：普通用户无需改代码即可导入、预览、保存并恢复一套完整动作包。

## 0.7：情侣共同空间

目标是从“桌面状态挂件”扩展为轻量共同记忆空间。

- 共同愿望清单和完成记录。
- 纪念日时间线与可控提醒。
- 照片墙和照片备注。
- 每日一句、晚安打卡或轻量陪伴任务。
- 双方共同确认后保存的重要时刻。
- 数据导出和单项删除。

完成标准：共同内容可跨设备一致显示；任何一方都能看见数据来源、权限和删除结果。

## 0.8：质量与跨平台准备

- 将核心同步、状态和数据模型拆成独立模块。
- 评估 Electron + React 或其他跨平台桌面技术，不为换技术而重写。
- Windows 自动更新和增量更新。
- macOS 原型，验证透明窗口、托盘和开机启动。
- 无障碍、键盘操作、不同 DPI 与多显示器适配。
- 自动化 UI 测试、安装测试和发布流水线。

## 1.0：正式产品

只有在留存、隐私和稳定性得到验证后再进入 1.0。

- 稳定的账号、绑定、同步、更新和客服流程。
- 清晰的免费能力与会员权益。
- 可选的主题、角色和动作包商店。
- 完整隐私政策、用户协议、内容规范和退款流程。
- 安全审计、数据备份、灾难恢复和运营监控。

不建议在早期加入信息流广告。情侣陪伴产品依赖信任，广告会明显削弱私密感。

## 暂不优先

- 完整即时聊天：微信、QQ 等产品已经成熟，彼端应保持轻量陪伴定位。
- 精确定位、摄像头常驻和键盘监控：隐私风险远大于产品价值。
- 复杂 3D 小屋和大型联机游戏：成本高，且尚未验证核心留存。
- 过早上线会员和支付：应先证明用户愿意长期使用基础陪伴功能。

## 建议验证指标

- 安装后成功看到桌宠的比例。
- 首次完成状态设置和双机连接的比例。
- 1 日、3 日、7 日仍保持使用的情侣对数。
- 每对情侣每天的状态更新、轻互动和留言次数。
- 同步失败率、崩溃率和平均连续运行时间。
- 主动关闭通知或卸载的原因。

这些指标用于发现体验问题，不应用来制造催促、焦虑或情侣间的监控压力。
